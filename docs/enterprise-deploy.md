# NexusLink — دليل النشر المؤسسي (M4.1 — عقد §38)

> النواة المحلية للنشر المؤسسي: سياسات مركزية بملف واحد + فرض لحظي + تقرير
> امتثال. ما يبقى خارجيًا: مدقق SOC 2/ISO، عقد OEM، والنفق/TLS للوصول عبر
> الإنترنت (حدود §38.هـ — القبول المؤسسي بقرار المالك).

## 1) الفكرة في سطرين

المؤسسة تنشر **ملف سياسة JSON واحدًا** على كل جهاز (بأي أداة MDM تكتب
ملفات)، فيفرض الجهاز السياسة لحظيًا فوق قرار مستخدمه (المُدار فوق
المستخدم)، ويعلن حالة الامتثال على `/api/enterprise/compliance` (حلقي —
بيد الجهاز). بلا ملف سياسة = الجهاز بيد مستخدمه بالكامل (الافتراضي
التاريخي، صفر تغيير).

## 2) مسارات ملف السياسة (بالترتيب)

| الأولوية | المسار | متى تستخدمه |
|---|---|---|
| 1 | `NEXUSLINK_POLICY_FILE` (متغير بيئة) | النشر حيث يتعدد مجلد العمل (حاويات/خدمات مخصصة) |
| 2 | Windows: `C:\ProgramData\NexusLink\policy.json` | MDM على ويندوز (ProgramData قابلة للكتابة بSYSTEM دون تدخل المستخدم) |
| 2 | macOS: `/Library/Application Support/NexusLink/policy.json` | MDM على ماك (مسار نظام — يقرؤه كل المستخدمين) |
| 2 | Linux: `/etc/nexuslink/policy.json` | حزم deb/AppImage على لينكس |

- **التعديل حي**: البوابة والمسارات تقرأ الملف بمتغير تعديل-الوقت عند كل
  نداء — تغيير أو حذف الملف يسري فورًا بلا إعادة تشغيل أي خدمة.
- **الصلاحيات**: الملف في مسار نظام يحتاج صلاحيات إدارية للكتابة — هذا
  مقصود (من يملك القرص يملك السياسة؛ مستخدم عادي لا يعيد توجيه الإدارة).
- **مخطط غير صالح = لا فرض** (فشل-آمن §38.هـ.3) والحالة تُعلن `invalid` في
  الامتثال — لا فرض جزئي ولا سلوك صامت.

## 3) المخطط v1 (المرجع الكامل في عقد §38.ج)

```json
{
  "schemaVersion": 1,
  "organization": "Acme Corp",
  "managed": {
    "remoteAccess": "force-off",
    "blockedBridges": [3005, 3006]
  }
}
```

| المفتاح | القيم | الفرض |
|---|---|---|
| `managed.remoteAccess` | `"force-off"` | كل واصل من خارج الجهاز يُرفض 403 ولو برمز صحيح؛ تفعيل/تدوير من الواجهة مرفوض — الوصول البعيد مؤسسيًا مغلق |
| | `"force-on"` | الرمز شرط دائم للخارج؛ تعطيل من الواجهة مرفوض (التدوير متروك — دورة الرمز بلا فجوة) |
| `managed.blockedBridges` | أعداد من 3003 إلى 3009 | جسور محددة محجوبة عن الواصل الخارجي (HTTP وWS) — loopback معفى دائمًا (الجهاز هي الحدود) |
| (غياب الملف) | — | غير مُدار: السلوك التاريخي حرفيًا |

## 4) القوالب الجاهزة (data/enterprise/)

| الملف | الغرض |
|---|---|
| `policy.template.json` | هيكل موثق بتعليقات — انسخ وعدّل |
| `examples/privacy-first.json` | وضع «الخصوصية افتراضيًا» لتحميلات OEM: وصول بعيد مغلق + جسور النقل محجوبة عن الخارج |
| `examples/field-kiosk.json` | أجهزة ميدانية/لوحات: رمز شرط دائم + نقل ملفات محجوب عن الخارج |

## 5) النشر الصامت لكل منصة (تثبيت التطبيق نفسه)

> المثبتات من [GitHub Releases](https://github.com/CTO-DRS/NexusLink/releases/latest) —
> حزمة MSI هي المفضلة لأدوات MDM على ويندوز، وAPK/AAB للإدارة المدارة على أندرويد.

### Windows (Intune / GPO / أي MDM يدعم MSI أو Win32)
```powershell
# MSI — صامت تمامًا (لا واجهة ولا إعادة تشغيل)
msiexec /i NexusLink_3.0.0_x64_en-US.msi /qn /norestart
# NSIS بديل
NexusLink_3.0.0_x64-setup.exe /S
```
- **Intune**: أضف تطبيق Win32 (IntuneWin) أو MSI مباشرة، ثم سكربت PowerShell
  للخطوة الثانية: `Copy-Item policy.json 'C:\ProgramData\NexusLink\'`.
- **ترتيب خطوتين**: ثبّت التطبيق ثم انسخ ملف السياسة — أو العكس؛ الفرض لحظي
  فلا فرق (التطبيق يلتقط الملف عند أول قراءة بعد وضعه).
- **GPO بلا Intune**: سكربت بدء تشغيل (Startup Script) ينسخ الملف إلى
  ProgramData — بلا سجل وبلا ADMX (حد §38.هـ.2: الملف مصدر الحقيقة الواحد).

### macOS (Jamf / MDM القياسي)
```bash
# تثبيت DMG بالبرمجة (غير موقّع — زر يمين Open للتشغيل الأول اليدوي، أو
# زر التحميل المسبق OEM بوضع الحارس الطرفي)
hdiutil attach NexusLink_3.0.0_aarch64.dmg -nobrowse
cp -R "/Volumes/NexusLink/NexusLink.app" /Applications/
hdiutil detach "/Volumes/NexusLink"
# ملف السياسة
mkdir -p "/Library/Application Support/NexusLink"
cp policy.json "/Library/Application Support/NexusLink/policy.json"
```
- **Jamf**: سياسة Install بعد payload ثم سياسة Files and Processes لنسخ
  الملف (أو Custom Settings لاحقًا إن انتقلت للقراءة من Managed Preferences
  — بند لاحق بقرار صريح، حد §38.هـ.2).

### Linux (deb / AppImage)
```bash
sudo apt install ./NexusLink_3.0.0_amd64.deb
sudo mkdir -p /etc/nexuslink && sudo cp policy.json /etc/nexuslink/policy.json
```

### Android (Managed Google Play / Intune / المدير المدار)
- ثبّت `app-release.aab` عبر Play المدار أو `NexusLink-3.0.0-release.apk`
  بأي MDM أندرويد (نشر صامت على الأجهزة المدارة بالكامل).
- ملف السياسة على أندرويد: عبر MDM انسخ الملف إلى التخزين الخارجي للتطبيق
  ومرّر المسار بمتغير البيئة `NEXUSLINK_POLICY_FILE` عند تشغيل خدمة الجهاز
  (بند تنفيذ أندرويد الكامل لقراءة managed config الأصلي: لاحق بقرار صريح).

## 6) التحقق بعد النشر (على كل جهاز)

```bash
# 1) البوابة تعلن الإدارة (بلا حساسيات):
curl -s http://127.0.0.1:81/__gw/health
#   → "policyManaged":true و"policyRemoteAccess" كما في الملف

# 2) تقرير الامتثال الكامل (حلقي — من الجهاز نفسه):
curl -s http://127.0.0.1:3000/api/enterprise/compliance
#   → policyState:"managed" + organization + policyHash + enforced + pairGate

# 3) بصمة السياسة تطابق الملف المنشور:
python3 - <<'PY'
import hashlib, json, sys
raw = open("policy.json","rb").read()
print(hashlib.sha256(raw).hexdigest()[:16])
PY
#   قارن الناتج مع policyHash في التقرير — تطابقه يثبت أن الفرض من ملفك
#   (بصمة §38.د — تثبت من الفرض والنشر بحجة واحدة).
```

## 7) الجولة الحية المرجعية

`node scripts/enterprise-e2e.mjs --app http://127.0.0.1:3000` — ‏26 فحصًا
حية (17 بوابة + 9 تطبيق) تشغّل نفس ما يوثقه §38.و: غير المُدار تاريخيًا،
force-off/force-on، حظر الجسور عن الخارج حصرًا، التعديل الحي، الفشل-آمن،

## 8) حدود صادقة (خلاصة §38.هـ)

1. القبول المؤسسي الموسع (نشر فعلي على عشرات الأجهزة/مدقق SOC 2/عقد OEM)
   خارجي بقرار المالك — هذا البند يجعل الجهاز *قابلًا* للإدارة لا *مُدارًا*.
2. لا قراءة سجل نظام (Registry/Preferences) — MDM ينشر الملف نفسه.
3. ملف غير صالح = لا فرض + `invalid` معلنة — لا فرض جزئي ولا صمت.
4. الحجب والقفل يمسان الخارج حصرًا — loopback معفى (الجهاز هي الحدود).
5. الامتثال حلقي فقط — التقارير المركزية عبر الشبكة بند النفق/TLS الخارجي
   (لا يُفتح بلا تصميم رموز وتدقيق — حد §36.هـ.1 الموروث).

## 9) السجل التدقيقي المؤسسي (عقد §39 — M4.2 نواة أدلة SOC 2)

### أين يكتب

| الأولوية | المسار | متى |
|---|---|---|
| 1 | `NEXUSLINK_AUDIT_FILE` (متغير بيئة) | النشر حيث يتعدد مجلد العمل |
| 2 | بجانب ملف السياسة المُدار: `…/NexusLink/audit.jsonl` أو `/etc/nexuslink/audit.jsonl` | الجهاز مُدار — مجلد يكتبه MDM = قابل للجمع مؤسسيًا |
| 3 | `<cwd>/.zstate/audit.jsonl` | جهاز غير مُدار (أدلة محلية بيد المستخدم) |

- **الشكل**: JSONL بسطر لكل حدث — حقول `i,t,k,ok,actor,d,prev,h` حيث `h`
  بصمة sha256:16 للسطر بترتيب الحقول العقدي (`i,t,k,ok,actor,d,prev`) و`prev`
  بصمة السطر السابق (فارغة عند الولادة). أي تعديل رجعي يكسر السلسلة ويُعلن.
- **الأحداث**: أفعال إدارة الاقتران (enable/rotate/disable) ورفوضها
  (قفل سياسة/حرس loopback بوسم خارجي/تعارض) ورصد انتقالات ملف السياسة
  (رصد أولي لكل دورة + كل تغير بحفظ from→to). بلا رموز خام ولا عناوين
  شبكة (حرس F6).
- **سلسلة مكسورة = السجل متجمد**: لا إلحاق فوق دليل مكسور إطلاقًا (تحذير
  صاخب في سجل الخدمة) وسلوك الإدارة نفسه سليم. **الدوران اليدوي**:
  أرشفة `audit.jsonl` (مثلًا `audit-2026Q4.jsonl`) ثم حذفه يفتح دورة
  جديدة يبدأها رصد أولي — أرشف الدورات معًا عند التدقيق.

### جمع الأدلة للمدقق الخارجي

```bash
# 1) حالة السلسلة من الجهاز (حلقي):
curl -s http://127.0.0.1:3000/api/enterprise/audit | python3 -m json.tool
#   → count + valid:true + head + آخر الأحداث

# 2) تحقق مستقل عن التطبيق (إعادة بناء البصمات ببايثون):
python3 - <<'PY'
import json, hashlib, sys
prev, exp = "", 1
for line in open(sys.argv[1], encoding="utf-8"):
    line = line.strip()
    if not line: continue
    r = json.loads(line)
    h = hashlib.sha256(json.dumps({k: r[k] for k in ("i","t","k","ok","actor","d","prev")}).encode()).hexdigest()[:16]
    assert r["i"] == exp and r["prev"] == prev and h == r["h"], f"chain broken at {r['i']}"
    prev, exp = r["h"], exp + 1
print(f"chain OK — {exp-1} records")
PY
#   audit.jsonl كالوسيط: python3 verify.py /etc/nexuslink/audit.jsonl

# 3) الأرشفة الدورية بأي أداة MDM: انسخ audit.jsonl إلى مشاركة مؤسسية
#    مع بصمة SHA256 للملف كله — السلاسل عبر الدورات تتحقق ملفًا ملفًا.
```

### حدود صادقة (خلاصة §39.هـ)

1. مدقق SOC 2/ISO والشهادة خارجيان بقرار المالك — الجهاز *مولد أدلة* لا *معتمدًا*.
2. كاتب واحد (خادم الويب) — رفض البوابة الخام يُعلن في health ولا يُكتب هنا؛
   الجمع المركزي عبر الشبكة بند النفق/TLS الخارجي (حد §38.هـ.5 الموروث).
3. كشف تعديل لا منعه — من يملك القرص يعيد بناء السلسلة كاملة (نموذج الجهاز المحلي).
4. الرصد عند القراءات الإدارية حصرًا — لا خيط خلفية ولا سطح جديد.

## 11) التحميل المسبق OEM — وضع «الخصوصية افتراضية» (عقد §40 — M4.3)

### الفكرة في سطرين

صورة النظام تُقلع NexusLink بعلم `NEXUSLINK_OEM_PRIVACY=1` فيولد الجهاز
**مغلقًا على الخارج كليًا** (حتى برمز اقتران صحيح) — ولا يُفتح إلا بملف
سياسة §38 يكتبه مدير النظام لاحقًا، والانتقال موثق في السجل التدقيقي §39.

### وضع العلم لكل منصة (بيئة العمليات — توريث قياسي)

```bash
# Linux (systemd — /etc/systemd/system/nexuslink.service):
[Service]
Environment=NEXUSLINK_OEM_PRIVACY=1
# وإن رغبت بقفل إضافي منذ الصورة (اختياري — العلم كافٍ وحده):
# mkdir -p /etc/nexuslink && cp privacy-first.json /etc/nexuslink/policy.json

# macOS (launchd — /Library/LaunchDaemons/com.nexuslink.app.plist):
<key>EnvironmentVariables</key>
<dict><key>NEXUSLINK_OEM_PRIVACY</key><string>1</string></dict>

# Windows (خدمة/غلاف MSI — بيئة النظام أو غلاف التشغيل):
setx /M NEXUSLINK_OEM_PRIVACY "1"   # أو عبر غلاف الخدمة قبل إقلاع العمليات
```

العلم يصل للعمليتين معًا بالوراثة (خادم الويب + البوابة) — لا ملف جديد
ولا مخطط جديد: ملف سياسة §38 يبقى أداة MDM، والسجل §39 كاتبًا واحدًا.

### ما يترتب على الجهاز المولود خاصًا (مفحوص 39 فحصًا — عقد §40.و)

- الخارج مرفوض 403 `remote-access-closed-oem-default` **ولو برمز صحيح** (HTTP وWS).
- كل الجسور (3003..3009) محجوبة عن الخارج دفاعًا ثانيًا خلف الباب الأمامي.
- loopback معفى دائمًا — الجهاز يعمل مع نفسه كاملًا (الجهاز هي الحدود).
- تفعيل/تدوير الاقتران من الواجهة مرفوضان 403 `oem-privacy-default` —
  والفكّ حصرًا بنشر ملف سياسة (فعل نظام إداري يوثقه السجل):
  `install -m 644 policy.json /etc/nexuslink/policy.json` ← تحت سياسة
  صالحة تعمل أقفال §38 وقواعدها حرفيًا (المصدر يعلن source=policy).
- ملف سياسة **غير صالح** على جهاز مولود خاصًا = **يبقى مغلقاً** (فشل-مغلق
  — عكس §38.هـ.3 المتعمد في وضع المستخدم) مع إعلان invalid في الامتثال.

### التحقق بعد التحميل المسبق (على كل جهاز)

```bash
# 1) البوابة تعلن الوضع:
curl -s http://127.0.0.1:81/__gw/health | grep -o '"oemPrivacy":[a-z]*'
#   → "oemPrivacy":true و"postureSource":"oem-default"
# 2) الامتثال الحلقي (من الجهاز نفسه):
curl -s http://127.0.0.1:3000/api/enterprise/compliance | python3 -c "import json,sys; j=json.load(sys.stdin); print(j['oemPrivacy'])"
#   → {'active': True, 'source': 'oem-default', 'effective': {... 'closed': True}}
# 3) الجولة الحية الكاملة على الجهاز:
node scripts/oem-e2e.mjs                            # المرحلتان أ+ب (25 فحصًا)
node scripts/oem-e2e.mjs --app http://127.0.0.1:3000  # المرحلة ج (14 فحصًا — بنفس متغيرات البيئة)
```

### حدود صادقة (خلاصة §40.هـ)

1. عقد OEM الفعلي وخطوط الإنتاج والقبول التجاري خارجية بقرار المالك —
   الجهاز *مولود خاص* لا *شريك OEM موقّع*.
2. العلم بيئي **كشف لا منع**: من يملك القرص وصلاحيات النظام قد يزيله من
   تعريف الخدمة — لا توقيع صورة ولا قفل boot في هذه النواة.
3. لا جمع مركزي للوضع — الامتثال حلقي والعلم محلي (بند النفق/TLS الخارجي).

## 12) النقل المشفر للبوابة — TLS ذاتي (عقد §41 — النواة المحلية لـ E4)

البوابة HTTP صافٍ بالتصميم (OFF بالتصميم — نمط §37/§38/§40). عند حاجة
الوصول المشفر المباشر (OEM/kiosk/شبكة موثوقة بلا وكيل خارجي) تُضبط
علمان بيئيان معًا في تعريف الخدمة نفسه الذي يضبط باقي أعلام NexusLink:

| المتغير | القيمة |
|---|---|
| `NEXUSLINK_TLS_CERT` | مسار ملف شهادة PEM (سلسلة كاملة إن وُجد وسطاء) |
| `NEXUSLINK_TLS_KEY` | مسار ملف المفتاح الخاص PEM |

### وضع العلم لكل منصة (الخدمة نفسها من §38/§40)

```bash
# systemd (Linux):
[Service]
Environment=NEXUSLINK_TLS_CERT=/etc/nexuslink/tls/cert.pem
Environment=NEXUSLINK_TLS_KEY=/etc/nexuslink/tls/key.pem

# launchd (macOS) — في plist:
<key>EnvironmentVariables</key>
<dict>
  <key>NEXUSLINK_TLS_CERT</key><string>/Library/Application Support/NexusLink/tls/cert.pem</string>
  <key>NEXUSLINK_TLS_KEY</key><string>/Library/Application Support/NexusLink/tls/key.pem</string>
</dict>

# Windows service — مفتاح سجل البيئة نفسه الذي يحمل NEXUSLINK_OEM_PRIVACY:
setx /M NEXUSLINK_TLS_CERT "C:\ProgramData\NexusLink\tls\cert.pem"
setx /M NEXUSLINK_TLS_KEY  "C:\ProgramData\NexusLink\tls\key.pem"
```

### توليد شهادة ذاتية التوقيع للشبكة المحلية (أداة النظام — بلا تبعية)

```bash
sudo mkdir -p /etc/nexuslink/tls && sudo openssl req -x509 -newkey rsa:2048 \
  -keyout /etc/nexuslink/tls/key.pem -out /etc/nexuslink/tls/cert.pem \
  -days 825 -nodes -subj "/CN=$(hostname)"
sudo chmod 600 /etc/nexuslink/tls/key.pem
```

لنطاق عام بشهادة CA/Let's Encrypt: يبقى **الوكيل الخارجي (Caddy/nginx)**
هو الموصى به (41.ب) — وقدرة البوابة الذاتية لسيناريوهات الوصول المباشر.

### السلوك التعاقدي (خلاصة §41)

- **بلا العلمين**: HTTP صافٍ حرفيًا كما كان — صفر تغيير وصفر حقن ترويسات.
- **بالعلمين معًا**: المُستمع HTTPS/WSS على المنفذ نفسه — WS يعبر مشفرًا
  بلا أي تعديل مسار، و`x-forwarded-proto: https` تُفرض للأعلى (تُستبدل أي
  قيمة واردة من العميل — الحقيقة من البوابة).
- **فشل-مغلق إقلاعي**: متغير واحد بلا الآخر، أو ملف غائب/تالف = الخدمة
  ترفض الإقلاع برسالة صاخبة (`REFUSING plaintext fallback`) — لا سقوط
  صامت إلى نص صريح أبدًا. أصلح المسارين أو أزل المتغيرين معًا.
- **التدوير**: الشهادة تُقرأ مرة عند الإقلاع — استبدل الملفين ثم
  `systemctl restart nexuslink` (أو مكافئه) — لا مراقبة حية للمفاتيخ.
- **التحقق بعد الإقلاع**:

```bash
curl -sk https://127.0.0.1:81/__gw/health \
  | python3 -c "import json,sys; j=json.load(sys.stdin); print(j['tls'], j['tlsFingerprint'])"
#   → True <16hex>  — وطابق البصمة مع:
openssl x509 -in /etc/nexuslink/tls/cert.pem -outform DER \
  | sha256sum | cut -c1-16
# الجولة الحية الكاملة:
node scripts/tls-e2e.mjs   # 16 فحصًا: TLS حي + فشل-مغلق + انحدار OFF
```

- **حدود صادقة (خلاصة §41.هـ)**: النفق والريلاي والنطاق وشهادات CA
  والمتطلبات التشغيلية للوصول عبر الإنترنت تبقى E4 خارجية بقرار مالك
  وعقد مؤسسي أول يحددها — mTLS بند عقدٍ إن جاء — والتدوير بإعادة تشغيل
  مقصودة لا إعادة تحميل حية.

## 13) سلسلة الثقة — التوقيع والـ notarization (عقد §43 — النوى النائمة لـ X1/X2)

سير الإصدار (`release.yml`) يحمل الآن خطوات توقيع **نائمة**: غياب الأسرار =
سلوك تاريخي حرفيًا (خطوات عبور صادقة تطبع تحذيرًا وتخرج 0)، ووجودها = توقيع
فعلي يُتحقق داخل CI نفسه قبل نشر أي أصل.

### 13.أ الأسرار المطلوبة (تُضاف من إعدادات المستودع — قرار المالك)

| السر | القيمة | ما يفعّله |
|---|---|---|
| `WINDOWS_PFX_BASE64` | شهادة Authenticode (OV ثم EV لاحقًا) بترميز base64 كامل | توقيع NSIS + MSI |
| `WINDOWS_PFX_PASSWORD` | كلمة سر ملف PFX | فك الشهادة عند الاستيراد |
| `APPLE_CERTIFICATE` | شهادة Developer ID Application (.p12) بترميز base64 | توقيع .app/.dmg |
| `APPLE_CERTIFICATE_PASSWORD` | كلمة سر p12 | فك الشهادة |
| `APPLE_SIGNING_IDENTITY` | اسم الهوية «Developer ID Application: …» | اختيار الهوية |
| `APPLE_ID` / `APPLE_PASSWORD` / `APPLE_TEAM_ID` | حساب Apple (كلمة سر خاصة بالتطبيق) | notarization + staple آلي |

### 13.ب ما يتغير لحظة توفير الأسرار (لا شيء غيره)

- **Windows**: خطوة الاستيراد تفك PFX وتستوردها إلى مخزن المستخدم (`CurrentUser\My`
  قابلة للتصدير) وتُخرج البصمة إلى `WIN_THUMBPRINT`؛ وعقل الإعدادات
  (`apps/desktop/signing-config.sh`) يضيف كتلة `bundle.windows`
  (`certificateThumbprint` + `digestAlgorithm: sha256` + طابع زمني DigiCert)
  إلى `--config` — الباندلر يوقّع NSIS وMSI — ثم تتحقق خطوة
  `Get-AuthenticodeSignature` من كل مثبت (Valid حصرًا وإلا فشل الجولة).
- **macOS**: المتغيرات الستة تُكتب في `GITHUB_ENV` حصرًا عند اكتمال بوابة
  كل منها (توقيع ≠ notarization — بوابتان مستقلتان)؛ الباندلر يوقّع
  بDeveloper ID ويقدّم للـ notarization ويُخرج أصل updater موقّعًا.
- **غياب الأسرار**: لا متغيرات تُمرر أصلًا (لا قيم فارغة توقع الباندلر
  خطأً) — CONFIG يُطابق سلسلتي التاريخ حرفيًا (فحص E2E وضعا 1/2).

### 13.ج التحقق اليدوي بعد التثبيت (يد المدقق/المشتري)

- Windows: `Get-AuthenticodeSignature "NexusLink_3.0.0_x64-setup.exe"`
  (Status=Valid + الموضوع + الطابع الزمني) — وSmartScreen لا يحذّر على
  جهاز نظيف (معيار قبول X1 الفعلي يتطلب شهادة OV+ أصلًا).
- macOS: `spctl --assess -v /Applications/NexusLink.app` (accepted) و
  `xcrun stapler validate /Applications/NexusLink.app` — وGatekeeper
  يفتح بنقرة عادية بلا «زر يمين ← Open» (معيار X2 الفعلي يتطلب حساب
  Apple Developer أصلًا).

### 13.د حدود صادقة (خلاصة §43.هـ)

- النوى محلية؛ **الشهادات والحسابات خارجية بقرار مالك** (OV ~$200–400/سنة
  · Apple $99/سنة) — لا تفعيل بلا أسرار ولا وعود بلا شهادة.
- التوقيع يشمل مثبتي NSIS/MSI وأصول updater — **portable.zip أرشيف**
  ومحتواه الداخلي لا يحمل Authenticode بذاته (حكم SmartScreen على
  المثبت الموقع) — و**desktop.yml** بناء فحصي بلا نشر يبقى بلا توقيع
  (الأصول الموزعة من release.yml حصرًا).
- EV أو Azure Trusted Signing (سمعة فورية) بند عقدٍ لاحق — البنية نفسها
  تقبل البصمة من أي مصدر يضعها في المتجر.

## 14) قناة Flathub — تعبئة المتجر (عقد §44 — النواة المحلية لـ X3)

بند X3 («Flathub أول دفع — حزمة مقبولة للمراجعة») نواته المحلية = **ملفات meta
الكاملة** التي تفحصها مراجعة Flathub، جاهزة للنسخ حرفيًا إلى فرع إرسال
`flathub/flathub` في مجلد `packaging/flathub/`. ما تبقى على المالك حصرًا: حساب
Flathub + بريد جهة الاتصال + فتح طلب الإرسال — **لا تحرير ملفات يلزمه**.

### 44.أ الأطروحة — غلاف AppImage المستخرَج لا بناء من مصدر

المستودع خاص والثنائي ذاتي الاكتفاء عمدًا (webkit2gtk 4.1 وGTK 3 وGStreamer
مضمّنة داخل `usr/lib` للحزمة) — فبناء Flatpak من مصدر يتطلب فتح المصدر وSDK
امتداد Rust. النمط المعتمد: **استخراج AppImage المنشورة ونسخ `usr/` كاملًا إلى
`/app`** — النمط المثبت لعشرات التطبيقات المملوكة على Flathub (منها Obsidian).
الغلاف المولّد أثناء البناء يعيد إنتاج خطّاف `linuxdeploy-plugin-gtk.sh` الخاص
بالـ AppImage حرفيًا بـ `APPDIR=/app` (المتغيرات الاثنا عشر نفسها) — أي أن
الحزمة تعيد إنتاج نفس التكوين الذي يعمل فعلًا في الإصدار المنشور، لا تكوينًا
مصمَّمًا من الصفر ولم يُجرَّب.

### 44.ب الحقيقة المؤسِّسة (لا افتراضات)

- التخطيط الداخلي فُحص فعليًا لِـ v3.0.0: `usr/bin/{nexuslink-desktop,node}` ·
  `usr/lib/NexusLink/{resources,vcam,vdd}` · `.desktop` باسم
  `NexusLink.desktop` و`StartupWMClass=nexuslink-desktop` — وكلها مقيدة في
  البيان والميتا بالبوابة الآلية.
- بصمة AppImage مثبتة في البيان (`b9a0ef5a…`) — **البوابة تقارنها حيًا بمدخل
  `SHA256SUMS.txt` المنشور** (شرطية الشبكة: تعذر الوصول = تخطٍّ صادق معلن
  لا إخفاق — درس §42).
- المعرف `sa.drs.nexuslink` = معرف Tauri في `tauri.conf.json` حرفيًا —
  بوابة التزامن عبري-الملفات تمنع الانجراف (نفس عقد التزامن المفروض على
  سجل الإصدارات: ميتا المتجر = سجل `/api/version` زوجيًا حرفيًا).

### 44.ج خطوات المالك (عند قرار الإرسال — من `packaging/flathub/README.md`)


### 44.د حدود صادقة (خلاصة §44.هـ)

1. **x86_64 حصرًا**: لا يوجد بناء aarch64 Linux منشور — البيان يصرّح

## 15) المساعدة عن بعد برمز قصير (عقد §46 — سيناريو العائلة)

> الحد الوحيد المتبقي من الجولة الخامسة مرحلة 3: اقتران **بلا مسح QR** — لمن
> لا يستطيع مسح شاشة (مساعدة قريب عبر مكالمة هاتفية). الرمز عددي ستّي
> يُقرأ هاتفيًا، والاقتران لا يكتمل إلا **بموافقة صريحة من مالك سطح المكتب**،
> والجلسة النشطة مرئية بلافتة حمراء مع **قطع بضغطة** من الطرفين.

### 46.أ الرياضيات (`src/lib/nexus/assist-code.ts`)

- الرمز **مشتق لا مخزَّن**: `HMAC-SHA256(سر آخر QR مُصدَر, "nexuslink/assist-code/v1")`
  ← ست خانات عشرية. حتمي (نفس السر = نفس الرمز) — تدوير QR يُدوّر الرمز
  تلقائيًا ولا حالة إضافية ولا تخزين.
- النافذة = نافذة سر الاقتران نفسها (G-1: عشر دقائق) — رمزان يتشاركان المصير.
- المقارنة زمن-ثابت (`timingSafeEqual` على طول متساوٍ — درس §6/§37).
- **سقف المحاولات §46.د = 5** على نافذة الاقتران الواحدة؛ استنفاده يقفل
  الطريق (locked) حتى إصدار QR جديد يعيد فتح السقف (كل نافذة بسقفها).
- التطبيع البشري: «123 456» و«123-456» تُقبل — الحروف والرموز تُرفض (malformed).

### 46.ب واجهة API (`/api/devices/assist` — نواة مغلقة)

| الإجراء | الجسم | السلوك |
|---|---|---|
| `GET` | — | لقطة الواجهة: `{active, code, expiresAt, attemptsLeft, pending, session}` — تستطلعها اللافتة كل 2.5ث |
| `POST request` | `{assistCode, name, model, kind, ip}` | من الهاتف: رمز صحيح → **طلب معلّق** (بلا تسجيل) + `pendingId` + `pollAfterMs: 1500`. رمز خاطئ → 403 `invalid` وينقص السقف (تدقيق warn) |
| `POST consent` | `{pendingId, accept}` | من الواجهة: القبول يسجّل الجهاز بنفس مسار الاقتران التعاقدي (idempotent بالاسم/المعرّف) ويفتح جلسة `via: "short-code"` — الرفض يطوي الطلب (تدقيق warn) |
| `POST cut` | — | **قطع بضغطة**: الجهاز offline + `trusted=false` (إبطال اقتران) وطي الجلسة والطلب — من لافتة المالك أو من تطبيق الوكيل |
| `POST dismiss` | `{pendingId}` | طي الطلب من جهة الوكيل (ألغى المحاولة) |

- `GET /api/devices/qr` يضيف إلى استجابته: `assistCode` و`assistExpiresAt`
  (ويتصفّر سقف المحاولات عند كل إصدار — السقف لكل نافذة لا للعملية).
- `GET /api/desktop/status` يضيف `desktop.assist = {pending, session}` — يقرؤه
  Rust واللافتة الحمراء في نافذة سطح المكتب.

### 46.ج الواجهة (سطح المكتب — منجزة ومفحوصة حيًا)

1. نافذة الاقتران تعرض تحت الرمز اليدوي كتلة **«رمز المساعدة (بديل المسح
   للعائلة)»** — الرمز الستّي بخط عريض + شرح السيناريو.
2. لافتة حية أعلى شاشة الأجهزة (`AssistBanner`): طلب معلّق → بطاقة كهرمانية
   باسم الجهاز وموديله وIP مع زرّي **قبول وفتح جلسة / رفض** — جلسة نشطة →
   لافتة حمراء `جلسة مساعدة نشطة مع {name}` وزر **قطع الجلسة**.
3. كل النصوص عبر المحرك التعاقدي (i18n §31): عشر مفاتيح جديدة في المعاجم
   الخمسة (en + fr/es/de/ru) — «رفض» المعجم الموجود (Decline) هو المستخدم.

### 46.د الهاتف (وكيل Flutter) — حدود صادقة (خلاصة §46.هـ)

بيئة التطوير الحالية بلا Flutter SDK — الجانب الهاتفي موثق هنا **كمواصفة
تنفيذ** تُبنى على جهاز المالك، والمصدر الوحيد للحقيقة لواجهات الشبكة هذا
الجدول في 46.ب حرفيًا:

1. **تبويب الاتصال**: زر «إدخال رمز المساعدة» بجوار مسح QR → حقل عددي ستّي
   (لوحة أرقام) + الاسم/الموديل تلقائيًا → `POST request` — وعرض
   «بانتظار موافقة مالك الكمبيوتر…» مع استطلاع `pendingId` كل 1.5ث حتى
   `consent` يرجع accepted/denied (عبر قراءة `GET` نفسه: `session` يعني قبول).
2. **إشعار أمامي دائم أثناء الجلسة**: قناة إشعار خاصة «جلسة مساعدة نشطة مع
   {deviceName}» مع إجراء **«قطع»** يستدعي `POST cut` ثم يوقف الجسور —
   النمط نفسه لخدمة الوكيل الأمامية القائمة (AgentForegroundService).
3. **أول قيمة**: بعد القبول يكمل الوكيل مساره التعاقدي الاعتيادي (تقرير report
   على جسوره) — لا مسار شبكي جديد غير جدول 46.ب.
4. **حد صادق**: حتى يُبنى الجانب الهاتفي، الطريق الكامل يعمل من **العميل
   الوِب** (`/?app=1`) على هاتف من تُساعده — إدخال الرمز صفحة ويب لا تطبيق؛
   والوظيفة كاملة محليًا بلا أي اعتماد خارجي.

### 46.هـ البوابة والدليل

بوابة `scripts/assist-e2e.mjs` — **41 فحصًا**: طور أ نقي 15 (حتمية الاشتقاق،
التطبيع، الشكل، النافذة، السقف، locked/malformed/expired/no-window) + طور ب
حي 26 ضد السيرفر (إصدار → خطأ → طلب → موافقة → status → قطع → رفض) —
**جولتان متتاليتان 41/41 أخضرتان** شرط إغلاق العقد كما في كل البوابات.

## 16) الإدارة المركزية الجماعية الموسّعة (عقد §47 — ما بعد ختم M4)

> أول بنود ما بعد ختم v3.0.0 بقرار المالك: تعميق §38 من «إدارة جهاز» إلى
> «إدارة أسطول» — مدير واحد يكتب ملفًا واحدًا فيسيطر على أسطول كامل:
> **قفل الإعدادات** (المستخدم لا يفكّ ما أقفله المدير) · **إجبار تدوير رمز
> الوصول** (لا رمز يعيش فوق أجله) · **تعطيل القدرات** (السوق/المساعدة/
> المزامنة العامة — لا يظهر زرها أصلًا) · **ختم الإصدار الأدنى** (لا تراجع
> تحت الأرضية المؤسسية) — وكلها لحظية بلا إعادة تشغيل (نمط §37 حرفيًا)،
> و**مولّد تقارير الامتثال** (JSON كامل + PDF إنجليزي صفر-اعتماد — تصدير
> محلي حصرًا)، و**حزم MDM التعريفية** جاهزة اللصق في Intune/Jamf/AnyMind
> تكتب مخطط السياسة نفسه حرفيًا.

### 47.أ المخطط v2 (توسيع §38 — توافق رجعي كامل)

```json
{
  "schemaVersion": 2,
  "organization": "Acme Corp",
  "managed": {
    "remoteAccess": "force-on",
    "blockedBridges": [],
    "lockedSettings": ["appLock", "updater"],
    "accessCodeRotationDays": 30,
    "disabledCapabilities": ["market"],
    "minimumVersion": "3.1.0"
  }
}
```

| المفتاح | القيم الصالحة | الفرض الفعلي |
|---|---|---|
| `managed.lockedSettings` | أسماء من `["appLock","idle","updater"]` | `PUT /api/desktop/settings` على قسم مقفول → **403** `settings-locked-by-policy` (الأقسام غير المقفولة تُكتب طبيعيًا — القفل انتقائي لا كلي) |
| `managed.accessCodeRotationDays` | عدد صحيح 1–365 | عمر رمز الاقتران (`createdAt` في ملف الرمز) فوق الأجلة → `rotationDue: true` في `/api/remote-access` وامتثال §38 والتقرير — والتدوير (`rotate`) وحده يصفّر العداد؛ **لا قطع ذاتي للرمز** (حد 47.و.2) |
| `managed.disabledCapabilities` | أسماء من `["market","assist","sync"]` | `market` → كل أفعال `POST /api/marketplace` → **403** `capability-disabled-by-policy` (GET يبقى قراءة صادقة) · `assist` → `POST /api/devices/assist` → **403** (مساعدة العائلة مطوية) · `sync` → القناة العامة `GET /api/sync/ops` (عقد §34) → **403** (قناة الوكيل الداخلية لا تُمسّ — الأجهزة المقترنة تعمل) |

قواعد الفرض الثلاث (موروثة §38 وتسري هنا): **مخطط غير صالح = لا فرض**
(فشل-آمن صاخب بحالة `invalid`) · **القراءة بمتغير تعديل-الوقت** في كل نداء
(تعديل/حذف الملف يسري فورًا بلا إعادة تشغيل أي خدمة) · **التوأم المطابق**:
البوابة (`mini-services/gateway/index.cjs`) تُحدِّث `parsePolicy` لتقبل v2
وتحكّم مفاتيحها الجديدة بالقواعد نفسها — حكم «صالح/غير صالح» واحد في
النسختين وإلا انشقّ الحسم (نمط §37: نسختان مطابقتان).

1. **لا سحابة MDM ولا قناة إدارة خارجية**: كل الحسم محلي من ملف على القرص

2. **التدوير المستحق لا يقطع الرمز ذاتيًا**: تجاوز الأجلة يُعلن صاخبًا

3. **ختم الإصدار الأدنى إعلان لا حجب**: الجهاز القديم يُعلَن تحت الأرضية

   (updater يرفض التراجع — §UPD) وعند بوابة النشر في مؤسسة تختار الرفض.
4. **PDF إنجليزي حصرًا**: قلم Helvetica قياسي بلا تشكيل عربي — النسخة
   العربية الكاملة عبر JSON والواجهة؛ دمج خط عربي مُشكَّل خارج نطاق هذا
   العقد بقرار موثق.
5. **تعطيل sync يغلق القناة العامة حصرًا** (`/api/sync/ops` — عقد §34):
   قناة الوكيل الداخلية (جسور prod) لا تُمسّ — الأجهزة المقترنة تعمل كاملًا؛
   حجب مزامنة الأجهزة نفسها قرار بنية أعمق يوثَّق عند طلبه.

## 17) وضع الطوارئ الذكي — القفل النهائي (عقد §48 — بند ما بعد الختم بطلب المالك)

> **أصل العقد — طلب المالك الحرفي**: «في حال سرقة الهاتف أو فقدانه نهائيًا
> يتم إغلاقه نهائيًا من NexusLink بواسطة إرسال ملف أو حزمة إلى الهاتف
> المستهدف الضائع أو المسروق فتقوم هذه الحزمة أو الملف بتثبيت نفسه
> تلقائيًا بدون علمه أو أي أحد». **الحد 48.و.1 يوثق الرفض الصريح**
> لجزء واحد من الطلب وينجز الهدف الحقيقي (الإغلاق النهائي) بالوضع الشريف
> المشروع: وكيل مسبق التثبيت بيد المالك حصرًا — نمط Find My.

### 48.أ الرفض الموثق (حدود صادقة قبل أي كود)

طلب «حزمة تثبّت نفسها خفيةً على المسروق بلا علم حامله» مرفوض بثلاث حجج:

1. **تقنيًا**: أندرويد وiOS يحظران التثبيت المُدار شبكيًا بلا تفاعل
   حامل الجهاز — لا سبيل لتنفيذه إلا استغلال ثغرة، واستغلال الثغرات
   في جهاز الغير هو تعريف برمجيات التجسس مهما كان الدافع.
2. **قانونيًا**: زرع أداة في جهاز لا تحمله بلا علم حامله جريمة في
   السعودية ومعظم الدول حتى لو كان جهازك المسروق — الأداة نفسها تعمل
   في الاتجاهين وتُستخدم ضدك لاحقًا.
3. **تعاقديًا (هويًا)**: المشروع قام على الحدود الصادقة (§26–§47) —
   قبول استثناء واحد يفكك العقد كله: ما ميزنا عن أدوات التجسس التجارية
   هو أن كل طرف في المنظومة يعرف ما يعمل عليه.

والهدف الحقيقي من الطلب («إغلاق نهائي عن بُعد») منجز كاملًا بالبنية
أدناه — ما رُفض هو الطريق الجرمي لا الغاية.

### 48.ب القتل النهائي أحادي الاتجاه (المصدر: الخادم بعد PIN)

- **المسار**: `POST /api/security/emergency` — بحرس loopback (نمط §37
  حرفيًا عبر `x-gw-client-ip`): واصل عبر البوابة من خارج الجهاز مرفوض
  403 حتى لو حمل كل أسرار الدنيا.
- **شروط القتل الثلاثة**: PIN بمطابقة زمن-ثابتة لهاش SHA-256 (يُخزَّن
  هاشًا حصرًا — خام لا يُخزَّن ولا يعود أبدًا) + كلمة «اقتل» حرفيًا
  (لا تُختار من قائمة ولا تُختصر — منع الطلقة العرضية) + معرّف جهاز
  موجّه (لا قتل «كل الأجهزة» ولا قتل عشوائي).
- **الأثر داخل الطلب نفسه**: إلحاق القائمة الدائمة + **تدوير رمز §37
  فورًا** (فتحة المسروق على واجهات سطح المكتب تُغلق لحظة القتل —
  `pairRotated` في الدليل) + إطلاق `dev:kill` على الوكيل المتصل إن
  وُجد + سجل §39 بأربعة أنواع جديدة
  (`emergency.arm/kill/kill.denied/kill.refired`).
- **مصدر الحقيقة الواحد**: ملف `.zstate/emergency-kill.json` (أو
  `NEXUSLINK_EMERGENCY_FILE`) بقراءة ديناميكية وكتابة ذرّية 0600 —
  صفر مخطط وصفر db (نمط §37): حذف الملف = غير مُسلَّح فورًا بلا إعادة
  تشغيل، والحشو الغريب يُرذل إلى الحالة الفارغة لا يُكسر السلوك.
- **لا حقن عبر المقبس**: `dev:kill` خارج قائمة ترحيل CMDS في جسر
  الحماية حرفيًا — القتل يولد من الخادم حصرًا بعد PIN (بث موجّه للسوكِت
  المسجل بمعرّفه)، ولا يمكن لأي عميل ويب أن «يأمر» بقتل أحد.

### 48.ج قائمة القتل عند إعادة الاتصال (حارس البروتوكول)

`guard:hello-phone` يفحص القائمة **قبل أي شيء**: المقتول العائد يُقابَل
بـ`dev:kill` فورًا — لا تسجيل وكيل، لا منارة، لا نقطة وسائط، ولا
مصافحة — مع تدقيق `emergency.kill.refired` (actor=remote). الجهاز
السليم يُسجَّل كالعادة: القائمة لا تبطئ البروتوكول إلا للمقتول حصرًا.
الإعادة على جهاز مقتول عبر الـAPI: خاملة صادقة (refired بلا أثر جديد).

### 48.د التصعيد الذاتي المحلي (يعمل بلا شبكة)

قواعد يُسلّحها المالك مسبقًا وتُدفع للهاتف عبر `guard:arm` عند التسليح
وعند كل تعديل: حد محاولات فتح فاشلة (3–10 بتطبيع صاخب معلن —
`normalizeArmRules` يوثق كل تقييد) + رصد تغيير شريحة
(`kill/warn/off`). الفرض على الهاتف نفسه بلا شبكة: نواة نقية
(`emergency-core.ts`) بدالة `decideSelfEscalation` **حتمية الترتيب**:
already-killed ← unlock-fails ← sim-changed (وnull القواعد = لا تصعيد
أبدًا). التوأم الوِب (`/phone`) يعرضها بمحاكاة معلنة (نمط prox:sim)
والتنفيذ الحقيقي في مواصفة وكيل Flutter (§46.د/§48.ز) على جهاز المالك.

### 48.هـ التوأم الهاتفي والبطاقة الثامنة

- **التوأم** (`phone-guard.tsx`): شاشة القتل الحمراء أولًا وقبل كل
  طبقة (z-400 فوق الرن والفقدان والمسح) بلا زر ولا مسار عودة — القتل
  يُرسَّخ في localStorage فإعادة التحميل لا تُنقذه؛ وكل معالجات
  الأوامر الأخرى تصير لا-عملة بعد القتل (صمت تام: لا إقرار ولا حالة).
- **البطاقة الثامنة** («الطوارئ الذكي» في الحماية): تسليح/قتل بكلمة
  حرفية/قائمة دائمة/الحدود الست معلنة قبل أي ضغطة.

### 48.و حدود صادقة (توقيع المالك عليها قبل الاستخدام)

1. **لا حزمة خفية**: الوكيل يُثبَّت مسبقًا بيد المالك حصرًا (نمط Find
   My) — ما رُفض في 48.أ لا يعود بأي صيغة، والهاتف المسروق قبل التسليح
   أو بعد فلاشه يبقى بلا وكيل.
2. **سياسة وتطبيق لا عتاد**: فلاش الجهاز يمحو الوكيل — يبقى سجل الأدلة
   عند المالك (جرمي-الاستخدام عند السلطات)؛ هذا ليس Apple Activation
   Lock على مستوى العتاد ويُعلَن كذلك.
3. **أحادي الاتجاه بلا API عودة**: لا «unkill» في أي مسار — إدارة
   الملف بيد مالك القرص داخل جهازه (إعادة تسليح جديدة لا «إلغاء»)؛
   القائمة تواجه أي إعادة اتصال بالقتل الفوري.
4. **نواقل موثوقة حصرًا**: التوصيل عبر الشبكة المحلية/إعادة اتصال
   معروفة/تصعيد محلي — لا سحابة وسيطة ولا قناة إنترنت عامة أبدًا (لا
   «إرسال حزمة عبر الهواء لأي مكان في العالم» — هذا عهر الوكلاء
   السحابيين الذي بنينا المشروع لرفضه).
5. **الإدارة loopback والـPIN يمنع الطلقة العرضية لا المدير**: من يملك
   القرص يملك الحسم — البوابة تحرس الخارج حتى لو حمل الرمز الصحيح.
6. **تدوير الرمز يعالج الأثر لا الهاتف**: إبطال §37 يغلق فتحة المسروق
   على واجهات سطح المكتب؛ الهاتف نفسه يعالجه وكيله (48.ج/48.د).

### 48.ز مواصفة الهاتف (تنفيذ على جهاز المالك — يندمج في §46.د)

وكيل Flutter يستقبل `guard:arm` (تخزين القواعد محليًا مع بصمة مصدر)،
يشغّل `decideSelfEscalation` عند كل محاولة فتح فاشلة/تغيير شريحة
(KeyguardManager/TelephonyCallback)، ويعرض شاشة القتل عند `dev:kill`
أو التصعيد — بلا أي مسار خروج في التطبيق (System Alert + قفل TaskStack)
حتى إعادة التشغيل تعيدها. البروتوكول مثبت هنا بالتوأم، والبناء
بيد المالك (حدود §46.د نفسها).

## 18) المرحّل الذاتي — وصول بلا وسيط (عقد §49 — النواة المحلية لـ E4)

> آخر ثغرة في وعد «بلا سحابة» كانت الوصول عبر الإنترنت نفسه: زوّد E4 الخارجي
> بنفق/ريلاي تجاري فيصبح الوعد منقوصًا. هذا العقد يغلقها محليًا: **مرحّل تملكه
> أنت** — خدمة مستقلة صفر-تبعيات تعمل على خادم المالك (VPS/منزلي) أنبوب تمرير
> أعمى بين جهازك البعيد ومركزك، والمركز يتصل بها خارجيًا (لا فتح منافذ في
> بيتك) والهاتف/المتصفح يصلان إليها فيصلان مركزك عبر مسار لا تلمسه أي سحابة.

### 49.أ البنية والمسار

```
هاتف/متصفح ──(WS مصادَق)── المرحّل (خادم المالك، صفر تخزين)
                                │ إطار TUNNEL (WS خارجي من المركز — تراجع حتمي)
                             النفق (relay-tunnel.ts داخل عملية Next على المركز)
                                │ HTTP loopback + ترويسة x-nexuslink-relay
                             البوابة §37 ── REST/الجسور كالمعتاد
```

- **النواة النقية** `src/lib/nexus/relay-core.ts`: اشتقاق الغرفة
  `HMAC-SHA256(السر, nexuslink/relay-room/v1) → 16-hex` (علنية العرض لا تمنح
  وصولًا) · إثبات الدخول `HMAC(السر, auth:nonce)` بمقارنة زمن-ثابتة — **السر
  لا يسافر في أي إطار أبدًا** · ترميز أطر JSON-نص فوق WS بسقف 12M محرفًا
  وأسباب رفض مغلقة (malformed/not-object/version/unknown-type/oversize/shape)
  · تطبيع طلب الزائر (إسقاط ترويسات القفزة والانتحال وتمرير الرمز) · تراجع
  إعادة اتصال حتمي صرف 250ms×2^n بسقف 16s.
- **الخادم** `mini-services/relay/server.mjs`: صفر تبعيات (WS يدوي على قاع
  RFC 6455) · **صفر تخزين** (لا ملفات ولا قاعدة ولا سجلات محتوى — حالة توجيه
  في الذاكرة، إعادة التشغيل تمحو كل شيء والنفق يعود) · غرفة واحدة = مركز
  واحد (السر نفسه = المشغّل نفسه — الجديد يزيح القديم بصراحة `replaced`) ·
  سقوف معلنة (5 زائرين/غرفة · 4 طلبات قيد خدمة/زائر · قفل IP بعد 5 فشلات
  مصادقة 10 دقائق · كشف nonce المُعاد داخل نافذة 10 دقائق) · نبض 15s والصمت
  ضعفه يقطع · مهلة مصادقة 5s · صحته `/__relay/health` صادقة عدّيًا ·
  `NEXUSLINK_TLS_CERT/KEY` بنمط §41 حرفيًا (فشل-مغلق: نصفهما يرفض الإقلاع)
  · **بلا `NEXUSLINK_RELAY_SECRET` لا يقلع أصلًا** (لا مرحّل مفتوحًا أبدًا) ·
  الربط الافتراضي 127.0.0.1 والتعريض قرار `--host 0.0.0.0` صريح.
- **النفق** `src/lib/nexus/relay-tunnel.ts` (داخل عملية Next — نمط الجسور):
  يتصل خارجيًا بالمرحّل ويوثّق كمركز، يخدم طلبات الزوار عبر **البوابة** لا
  REST مباشرة (نقطة الحسم الواحدة) بترويسة شدّ `x-nexuslink-relay`، مهلة طلب
  30s، جسم ≤ 8MiB، إحصاءات F6-آمنة (طلبات/بايتات — لا محتوى).
- **الإدارة** `/api/relay` (نمط §37 حرفيًا): GET حالة حية بلا سر · POST
  enable/disable بحرس loopback (`x-gw-client-ip`) وقفل السياسة (force-off
  يمنع التفعيل · المولود خاصًا يمنعه) · مصدر الحقيقة ملف خارج المخطط
  `.zstate/relay.json` ذرّي 0600 — حذفه/تعطيله = قطع فوري بلا إعادة تشغيل ·
  سجل §39 بثلاثة أنواع (relay.enable/disable/admin.denied) ببصمة السر لا
  السر. البطاقة في إعدادات سطح المكتب (18 مفتاح i18n ×5 — تطابق كامل

### 49.ب تكامل الثقة مع §37/§38/§40 (ترويسة الشدة)

النفق يضبط `x-nexuslink-relay: <الغرفة>` على كل طلب يمرر للبوابة، والبوابة
تعامل حاملها **كواصل خارجي** في حواجزها الثلاثة (رمز §37 · فرض السياسة ·
حجب الجسور). خاصية الأمان: وجود الترويسة **يشدّ أبدًا ولا يرخي أبدًا** — واصل
الشبكة الحقيقي خارجي أصلًا فلا يغيرها أثرًا، وواصل loopback لا يستطيع
استعمالها إلا ليعامل أشدّ (لا مسار نفاذ عبرها إطلاقًا). النتيجة الحية:
الهاتف البعيد عبر المرحّل يحمل رمز §37 كما يحمله على الشبكة المحلية —
بلا رمز 401 وبالرمز 200 (مفحوص عبر البوابة الحقيقية)، وسياسة force-off
تغلق النفق من جذر تفعيله، وloopback المباشر بلا الترويسة معفى كما كان
حرفيًا (انحدار مفحوص).

### 49.ج حدود صادقة (§49.هـ)

1. **المرحّل يرى البيانات الوصفية** (العناوين والتوقيت والأحجام) — لا
   محتوى القنوات المعمّاة (E2EE قائم يُمرَّر مختومًا)، لكن نداءات REST
   غير المغلّفة تُرى للمرحّل إن أنهى TLS؛ تشغيل الإنترنت العام عبر Caddy
   أمام المرحّل (نمط §41.ب) أو علمي TLS الذاتيين — والثقة انتقلت من مزود
   سحابي إلى صندوق تملكه أنت، ولم تُلغَ.
2. **v1 يمرر HTTP/REST حصرًا**: قنوات المقبس الحي (Socket.IO/NexusLive UDP)
   محلية ولا تعبر المرحّل — بند توسعة معلن لا وعدًا غامضًا.
3. **سقوط المرحّل يسقط الوصول البعيد فقط**: الشبكة المحلية بلا أي تغيير
   (النفق OFF بالتصميم لا يدخل مسار LAN أبدًا) والتراجع الحتمي يعيد الاتصال
   عند عودته (مفحوص بإعادة تشغيل حية).
4. **السر واحد = مشغّل واحد**: مركزان بنفس السر يتنافسان (الجديد يزيح
   القديم) — سلوك معلن للمالك الواحد، لا دعم متعدد المشغلين.
5. **الإغفال الصادق**: تفعيل النفق مع رمز §37 معطّل = الوصول مفتوح لكل من
   يحمل إثبات السر (سلوك §37 التاريخي حرفيًا) — البطاقة تحذّر بصريًا
   (`فعّل رمز الوصول البعيد أولًا`) والمسار لا يقفل (تذكير لا وصاية).
6. **mTLS وتدوير الشهادة الحي ووكيل عكسي بديل**: بنود عقد لاحق إن جاء
   (النمط الموروث §41.هـ) — والتدوير بإعادة تشغيل مقصودة.
7. **خلف وكيل عكسي**: المرحّل يستخدم عنوان المقبس لا ترويسات الوكيل —
   عناوين الزوار تظهر كعنوان الوكيل (معلن؛ القفل بالمقبس يبقى فعالًا).
