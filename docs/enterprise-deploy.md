# NexusLink — دليل النشر المؤسسي (M4.1 — عقد §38)

> النواة المحلية للنشر المؤسسي: سياسات مركزية بملف واحد + فرض لحظي + تقرير
> امتثال. ما يبقى خارجيًا: مدقق SOC 2/ISO، عقد OEM، والنفق/TLS للوصول عبر
> الإنترنت (حدود §38.هـ — القبول المؤسسي بقرار المالك).

## 1) الفكرة في سطرين

المؤسسة تنشر **ملف سياسة JSON واحدًا** على كل جهاز (بأي أداة MDM تكتب
ملفات)، فيفرض الجهاز السياسة لحظيًا فوق قرار مستخدمه (المُدار فوق
المستخدم)، ويعلن حالة الامتثال على `/api/enterprise/compliance` (حلقي —
بيد الجهاز). بلا ملف سياسة = الجهاز بيد مستخدمه بالكامل (الافتراضي
التاريخي، صفر تغيير).

## 2) مسارات ملف السياسة (بالترتيب)

| الأولوية | المسار | متى تستخدمه |
|---|---|---|
| 1 | `NEXUSLINK_POLICY_FILE` (متغير بيئة) | النشر حيث يتعدد مجلد العمل (حاويات/خدمات مخصصة) |
| 2 | Windows: `C:\ProgramData\NexusLink\policy.json` | MDM على ويندوز (ProgramData قابلة للكتابة بSYSTEM دون تدخل المستخدم) |
| 2 | macOS: `/Library/Application Support/NexusLink/policy.json` | MDM على ماك (مسار نظام — يقرؤه كل المستخدمين) |
| 2 | Linux: `/etc/nexuslink/policy.json` | حزم deb/AppImage على لينكس |

- **التعديل حي**: البوابة والمسارات تقرأ الملف بمتغير تعديل-الوقت عند كل
  نداء — تغيير أو حذف الملف يسري فورًا بلا إعادة تشغيل أي خدمة.
- **الصلاحيات**: الملف في مسار نظام يحتاج صلاحيات إدارية للكتابة — هذا
  مقصود (من يملك القرص يملك السياسة؛ مستخدم عادي لا يعيد توجيه الإدارة).
- **مخطط غير صالح = لا فرض** (فشل-آمن §38.هـ.3) والحالة تُعلن `invalid` في
  الامتثال — لا فرض جزئي ولا سلوك صامت.

## 3) المخطط v1 (المرجع الكامل في عقد §38.ج)

```json
{
  "schemaVersion": 1,
  "organization": "Acme Corp",
  "managed": {
    "remoteAccess": "force-off",
    "blockedBridges": [3005, 3006]
  }
}
```

| المفتاح | القيم | الفرض |
|---|---|---|
| `managed.remoteAccess` | `"force-off"` | كل واصل من خارج الجهاز يُرفض 403 ولو برمز صحيح؛ تفعيل/تدوير من الواجهة مرفوض — الوصول البعيد مؤسسيًا مغلق |
| | `"force-on"` | الرمز شرط دائم للخارج؛ تعطيل من الواجهة مرفوض (التدوير متروك — دورة الرمز بلا فجوة) |
| `managed.blockedBridges` | أعداد من 3003 إلى 3009 | جسور محددة محجوبة عن الواصل الخارجي (HTTP وWS) — loopback معفى دائمًا (الجهاز هي الحدود) |
| (غياب الملف) | — | غير مُدار: السلوك التاريخي حرفيًا |

## 4) القوالب الجاهزة (data/enterprise/)

| الملف | الغرض |
|---|---|
| `policy.template.json` | هيكل موثق بتعليقات — انسخ وعدّل |
| `examples/privacy-first.json` | وضع «الخصوصية افتراضيًا» لتحميلات OEM: وصول بعيد مغلق + جسور النقل محجوبة عن الخارج |
| `examples/field-kiosk.json` | أجهزة ميدانية/لوحات: رمز شرط دائم + نقل ملفات محجوب عن الخارج |

## 5) النشر الصامت لكل منصة (تثبيت التطبيق نفسه)

> المثبتات من [GitHub Releases](https://github.com/CTO-DRS/NexusLink/releases/latest) —
> حزمة MSI هي المفضلة لأدوات MDM على ويندوز، وAPK/AAB للإدارة المدارة على أندرويد.

### Windows (Intune / GPO / أي MDM يدعم MSI أو Win32)
```powershell
# MSI — صامت تمامًا (لا واجهة ولا إعادة تشغيل)
msiexec /i NexusLink_3.0.0_x64_en-US.msi /qn /norestart
# NSIS بديل
NexusLink_3.0.0_x64-setup.exe /S
```
- **Intune**: أضف تطبيق Win32 (IntuneWin) أو MSI مباشرة، ثم سكربت PowerShell
  للخطوة الثانية: `Copy-Item policy.json 'C:\ProgramData\NexusLink\'`.
- **ترتيب خطوتين**: ثبّت التطبيق ثم انسخ ملف السياسة — أو العكس؛ الفرض لحظي
  فلا فرق (التطبيق يلتقط الملف عند أول قراءة بعد وضعه).
- **GPO بلا Intune**: سكربت بدء تشغيل (Startup Script) ينسخ الملف إلى
  ProgramData — بلا سجل وبلا ADMX (حد §38.هـ.2: الملف مصدر الحقيقة الواحد).

### macOS (Jamf / MDM القياسي)
```bash
# تثبيت DMG بالبرمجة (غير موقّع — زر يمين Open للتشغيل الأول اليدوي، أو
# زر التحميل المسبق OEM بوضع الحارس الطرفي)
hdiutil attach NexusLink_3.0.0_aarch64.dmg -nobrowse
cp -R "/Volumes/NexusLink/NexusLink.app" /Applications/
hdiutil detach "/Volumes/NexusLink"
# ملف السياسة
mkdir -p "/Library/Application Support/NexusLink"
cp policy.json "/Library/Application Support/NexusLink/policy.json"
```
- **Jamf**: سياسة Install بعد payload ثم سياسة Files and Processes لنسخ
  الملف (أو Custom Settings لاحقًا إن انتقلت للقراءة من Managed Preferences
  — بند لاحق بقرار صريح، حد §38.هـ.2).

### Linux (deb / AppImage)
```bash
sudo apt install ./NexusLink_3.0.0_amd64.deb
sudo mkdir -p /etc/nexuslink && sudo cp policy.json /etc/nexuslink/policy.json
```

### Android (Managed Google Play / Intune / المدير المدار)
- ثبّت `app-release.aab` عبر Play المدار أو `NexusLink-3.0.0-release.apk`
  بأي MDM أندرويد (نشر صامت على الأجهزة المدارة بالكامل).
- ملف السياسة على أندرويد: عبر MDM انسخ الملف إلى التخزين الخارجي للتطبيق
  ومرّر المسار بمتغير البيئة `NEXUSLINK_POLICY_FILE` عند تشغيل خدمة الجهاز
  (بند تنفيذ أندرويد الكامل لقراءة managed config الأصلي: لاحق بقرار صريح).

## 6) التحقق بعد النشر (على كل جهاز)

```bash
# 1) البوابة تعلن الإدارة (بلا حساسيات):
curl -s http://127.0.0.1:81/__gw/health
#   → "policyManaged":true و"policyRemoteAccess" كما في الملف

# 2) تقرير الامتثال الكامل (حلقي — من الجهاز نفسه):
curl -s http://127.0.0.1:3000/api/enterprise/compliance
#   → policyState:"managed" + organization + policyHash + enforced + pairGate

# 3) بصمة السياسة تطابق الملف المنشور:
python3 - <<'PY'
import hashlib, json, sys
raw = open("policy.json","rb").read()
print(hashlib.sha256(raw).hexdigest()[:16])
PY
#   قارن الناتج مع policyHash في التقرير — تطابقه يثبت أن الفرض من ملفك
#   (بصمة §38.د — تثبت من الفرض والنشر بحجة واحدة).
```

## 7) الجولة الحية المرجعية

`node scripts/enterprise-e2e.mjs --app http://127.0.0.1:3000` — ‏26 فحصًا
حية (17 بوابة + 9 تطبيق) تشغّل نفس ما يوثقه §38.و: غير المُدار تاريخيًا،
force-off/force-on، حظر الجسور عن الخارج حصرًا، التعديل الحي، الفشل-آمن،
قفل الأفعال، والامتثال حلقيًا وعبر البوابة.

## 8) حدود صادقة (خلاصة §38.هـ)

1. القبول المؤسسي الموسع (نشر فعلي على عشرات الأجهزة/مدقق SOC 2/عقد OEM)
   خارجي بقرار المالك — هذا البند يجعل الجهاز *قابلًا* للإدارة لا *مُدارًا*.
2. لا قراءة سجل نظام (Registry/Preferences) — MDM ينشر الملف نفسه.
3. ملف غير صالح = لا فرض + `invalid` معلنة — لا فرض جزئي ولا صمت.
4. الحجب والقفل يمسان الخارج حصرًا — loopback معفى (الجهاز هي الحدود).
5. الامتثال حلقي فقط — التقارير المركزية عبر الشبكة بند النفق/TLS الخارجي
   (لا يُفتح بلا تصميم رموز وتدقيق — حد §36.هـ.1 الموروث).

## 9) السجل التدقيقي المؤسسي (عقد §39 — M4.2 نواة أدلة SOC 2)

### أين يكتب

| الأولوية | المسار | متى |
|---|---|---|
| 1 | `NEXUSLINK_AUDIT_FILE` (متغير بيئة) | النشر حيث يتعدد مجلد العمل |
| 2 | بجانب ملف السياسة المُدار: `…/NexusLink/audit.jsonl` أو `/etc/nexuslink/audit.jsonl` | الجهاز مُدار — مجلد يكتبه MDM = قابل للجمع مؤسسيًا |
| 3 | `<cwd>/.zstate/audit.jsonl` | جهاز غير مُدار (أدلة محلية بيد المستخدم) |

- **الشكل**: JSONL بسطر لكل حدث — حقول `i,t,k,ok,actor,d,prev,h` حيث `h`
  بصمة sha256:16 للسطر بترتيب الحقول العقدي (`i,t,k,ok,actor,d,prev`) و`prev`
  بصمة السطر السابق (فارغة عند الولادة). أي تعديل رجعي يكسر السلسلة ويُعلن.
- **الأحداث**: أفعال إدارة الاقتران (enable/rotate/disable) ورفوضها
  (قفل سياسة/حرس loopback بوسم خارجي/تعارض) ورصد انتقالات ملف السياسة
  (رصد أولي لكل دورة + كل تغير بحفظ from→to). بلا رموز خام ولا عناوين
  شبكة (حرس F6).
- **سلسلة مكسورة = السجل متجمد**: لا إلحاق فوق دليل مكسور إطلاقًا (تحذير
  صاخب في سجل الخدمة) وسلوك الإدارة نفسه سليم. **الدوران اليدوي**:
  أرشفة `audit.jsonl` (مثلًا `audit-2026Q4.jsonl`) ثم حذفه يفتح دورة
  جديدة يبدأها رصد أولي — أرشف الدورات معًا عند التدقيق.

### جمع الأدلة للمدقق الخارجي

```bash
# 1) حالة السلسلة من الجهاز (حلقي):
curl -s http://127.0.0.1:3000/api/enterprise/audit | python3 -m json.tool
#   → count + valid:true + head + آخر الأحداث

# 2) تحقق مستقل عن التطبيق (إعادة بناء البصمات ببايثون):
python3 - <<'PY'
import json, hashlib, sys
prev, exp = "", 1
for line in open(sys.argv[1], encoding="utf-8"):
    line = line.strip()
    if not line: continue
    r = json.loads(line)
    h = hashlib.sha256(json.dumps({k: r[k] for k in ("i","t","k","ok","actor","d","prev")}).encode()).hexdigest()[:16]
    assert r["i"] == exp and r["prev"] == prev and h == r["h"], f"chain broken at {r['i']}"
    prev, exp = r["h"], exp + 1
print(f"chain OK — {exp-1} records")
PY
#   audit.jsonl كالوسيط: python3 verify.py /etc/nexuslink/audit.jsonl

# 3) الأرشفة الدورية بأي أداة MDM: انسخ audit.jsonl إلى مشاركة مؤسسية
#    مع بصمة SHA256 للملف كله — السلاسل عبر الدورات تتحقق ملفًا ملفًا.
```

### حدود صادقة (خلاصة §39.هـ)

1. مدقق SOC 2/ISO والشهادة خارجيان بقرار المالك — الجهاز *مولد أدلة* لا *معتمدًا*.
2. كاتب واحد (خادم الويب) — رفض البوابة الخام يُعلن في health ولا يُكتب هنا؛
   الجمع المركزي عبر الشبكة بند النفق/TLS الخارجي (حد §38.هـ.5 الموروث).
3. كشف تعديل لا منعه — من يملك القرص يعيد بناء السلسلة كاملة (نموذج الجهاز المحلي).
4. الرصد عند القراءات الإدارية حصرًا — لا خيط خلفية ولا سطح جديد.

## 11) التحميل المسبق OEM — وضع «الخصوصية افتراضية» (عقد §40 — M4.3)

### الفكرة في سطرين

صورة النظام تُقلع NexusLink بعلم `NEXUSLINK_OEM_PRIVACY=1` فيولد الجهاز
**مغلقًا على الخارج كليًا** (حتى برمز اقتران صحيح) — ولا يُفتح إلا بملف
سياسة §38 يكتبه مدير النظام لاحقًا، والانتقال موثق في السجل التدقيقي §39.

### وضع العلم لكل منصة (بيئة العمليات — توريث قياسي)

```bash
# Linux (systemd — /etc/systemd/system/nexuslink.service):
[Service]
Environment=NEXUSLINK_OEM_PRIVACY=1
# وإن رغبت بقفل إضافي منذ الصورة (اختياري — العلم كافٍ وحده):
# mkdir -p /etc/nexuslink && cp privacy-first.json /etc/nexuslink/policy.json

# macOS (launchd — /Library/LaunchDaemons/com.nexuslink.app.plist):
<key>EnvironmentVariables</key>
<dict><key>NEXUSLINK_OEM_PRIVACY</key><string>1</string></dict>

# Windows (خدمة/غلاف MSI — بيئة النظام أو غلاف التشغيل):
setx /M NEXUSLINK_OEM_PRIVACY "1"   # أو عبر غلاف الخدمة قبل إقلاع العمليات
```

العلم يصل للعمليتين معًا بالوراثة (خادم الويب + البوابة) — لا ملف جديد
ولا مخطط جديد: ملف سياسة §38 يبقى أداة MDM، والسجل §39 كاتبًا واحدًا.

### ما يترتب على الجهاز المولود خاصًا (مفحوص 39 فحصًا — عقد §40.و)

- الخارج مرفوض 403 `remote-access-closed-oem-default` **ولو برمز صحيح** (HTTP وWS).
- كل الجسور (3003..3009) محجوبة عن الخارج دفاعًا ثانيًا خلف الباب الأمامي.
- loopback معفى دائمًا — الجهاز يعمل مع نفسه كاملًا (الجهاز هي الحدود).
- تفعيل/تدوير الاقتران من الواجهة مرفوضان 403 `oem-privacy-default` —
  والفكّ حصرًا بنشر ملف سياسة (فعل نظام إداري يوثقه السجل):
  `install -m 644 policy.json /etc/nexuslink/policy.json` ← تحت سياسة
  صالحة تعمل أقفال §38 وقواعدها حرفيًا (المصدر يعلن source=policy).
- ملف سياسة **غير صالح** على جهاز مولود خاصًا = **يبقى مغلقاً** (فشل-مغلق
  — عكس §38.هـ.3 المتعمد في وضع المستخدم) مع إعلان invalid في الامتثال.

### التحقق بعد التحميل المسبق (على كل جهاز)

```bash
# 1) البوابة تعلن الوضع:
curl -s http://127.0.0.1:81/__gw/health | grep -o '"oemPrivacy":[a-z]*'
#   → "oemPrivacy":true و"postureSource":"oem-default"
# 2) الامتثال الحلقي (من الجهاز نفسه):
curl -s http://127.0.0.1:3000/api/enterprise/compliance | python3 -c "import json,sys; j=json.load(sys.stdin); print(j['oemPrivacy'])"
#   → {'active': True, 'source': 'oem-default', 'effective': {... 'closed': True}}
# 3) الجولة الحية الكاملة على الجهاز:
node scripts/oem-e2e.mjs                            # المرحلتان أ+ب (25 فحصًا)
node scripts/oem-e2e.mjs --app http://127.0.0.1:3000  # المرحلة ج (14 فحصًا — بنفس متغيرات البيئة)
```

### حدود صادقة (خلاصة §40.هـ)

1. عقد OEM الفعلي وخطوط الإنتاج والقبول التجاري خارجية بقرار المالك —
   الجهاز *مولود خاص* لا *شريك OEM موقّع*.
2. العلم بيئي **كشف لا منع**: من يملك القرص وصلاحيات النظام قد يزيله من
   تعريف الخدمة — لا توقيع صورة ولا قفل boot في هذه النواة.
3. لا جمع مركزي للوضع — الامتثال حلقي والعلم محلي (بند النفق/TLS الخارجي).
