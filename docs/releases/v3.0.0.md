## العربية

**NexusLink v3.0.0** — إصدار الثقل المؤسسي: جهاز «قابل للإدارة» و«مولد أدلة»
و«مولود خاص» — الإدارة المركزية والسجل التدقيقي ووضع OEM «خصوصية افتراضية»،
وكل ذلك على الجهاز نفسه بلا خدمة سحابية ولا بايت يغادر الشبكة المحلية.

### جديد

**النشر المؤسسي (عقد §38 — M4.1)** — مخطط سياسة مركزية v1 صفر-مخطط: حقل
`remoteAccess` ‏(`force-on`/`force-off`) وحقل `blockedBridges` بقائمة جسور
مغلقة؛ حل مسارَي موثق (`NEXUSLINK_POLICY_FILE` ثم بجانب ملف الاقتران ثم
`.zstate/enterprise-policy.json`) وكاش mtime بفرض لحظي في البوابة (فرض
`force-off` قبل حسم الرمز + بوابة `policyBridgeGate` على HTTP وWS + `policyManaged`
في health) وفي المسارات (`/api/remote-access` تلميح سياسة وقفل أفعال التعارض)؛
تقرير امتثال حلقي `/api/enterprise/compliance` ببصمة ملف السياسة (sha256:16)؛
بطاقة إعدادات صادقة تخفي الأزرار المتعارضة بدل تعطيلها صامتًا؛ ودليل النشر
`docs/enterprise-deploy.md` مع قوالب MDM جاهزة (مسارات + أوامر صامتة لكل منصة
+ تحقق بالبصمة) — الجهاز «قابل للإدارة» من وحدة MDM واحدة بلا لمسة يد.

**أدلة شهادات الثقة (عقد §39 — M4.2)** — سجل تدقيقي مؤسسي على الجهاز: JSONL
إلحاقي بسلسلة بصمات (`h = sha256:16` للسطر و`prev` بصمة سابقه — كشف تعديل
رجعي لا منعه، نموذج الجهاز المحلي الصادق)؛ كاتب واحد حصرًا (خادم الويب) بطابور
داخلي وتحقق سلسلة كامل قبل كل إلحاق و`fsync` — الدليل قبل السرعة؛ سلسلة
مكسورة = سجل متجمد (لا إلحاق فوق دليل مكسور إطلاقًا)؛ أحداث مغلقة المجموعة:
أفعال الاقتران ببصمات لا رموز، ورفوض الإدارة بسببية كاملة (دليل أمني بحد
ذاته)، ورصد انتقالات السياسة `from→to` (إدارة التغيير)؛ نقطة عرض حلقي
`/api/enterprise/audit` تعيد صحة السلسلة بإعادة بناء كل بصمة و`brokenAt`
ورأس السجل — منظر لا إجراء؛ ودليل جمع للأدلة بيد المدقق الخارجي مع سكربت
تحقق بايثون مستقل — الجهاز «مولد أدلة» جاهزة ليد المدقق (الشهادة نفسها —
SOC 2 Type I — تبقى قبولًا خارجيًا بقرار المالك).

**وضع OEM «خصوصية افتراضية» (عقد §40 — M4.3)** — علم بيئي واحد
`NEXUSLINK_OEM_PRIVACY=1` تضعه صورة النظام (systemd/launchd/خدمة ويندوز)
فيولد الجهاز «مولودًا خاصًا»: بلا سياسة صالحة = الخارج مرفوض كليًا ولو برمز
اقتران صحيح (HTTP وWS) وكل الجسور محجوبة دفاعًا ثانيًا، وفشل-مغلق (ملف تالف
لا يفتح جهازًا مولودًا خاصًا — عكس الفشل-الآمن نحو المستخدم المتعمد في وضع
§38)، والتخفيف حصرًا بملف سياسة §38 صالح (مسار MDM — قفل التخفيف الذاتي
عمدًا)؛ بلا علم: السلوك التاريخي حرفيًا صفر تغيير؛ التوصيف كامل في تقرير
الامتثال والبطاقتين والانتقالات موثقة في سجل §39 — فوق قالب
`privacy-first.json` الجاهز، بلا مخطط جديد ولا ملف جديد (نمط §37/§38: مصدر
حقيقة واحد).

**حدود صادقة بصدق الوثائق** — ما يبقى خارجيًا بعد هذا الإصدار (قبول مؤسسي
بقرار المالك حصرًا): النشر الصامت الفعلي على 50 جهازًا (E1)؛ مدقق SOC 2
والشهادة (E2)؛ عقد OEM وخطوط الإنتاج (E3)؛ والنفق والنطاق وTLS للوصول عبر
الإنترنت بعقد مؤسسي أول يحدد المتطلبات (E4 — حد §36.هـ.1 الخارجي). النوى
المحلية الأربعة لهذه البنود منجزة ومفحوصة (§38 + §39 + §40 + WEB §36/PAIR §37).

**التوثيق المرفق** — `docs/enterprise-deploy.md` موسع (§9–§11: جمع الأدلة
للمدقق + الدوران اليدوي + وضع العلم لكل منصة) و`docs/MASTER-PLAN.md` §5.ب
محدث (E1–E4 بنوى محلية منجزة) وقوالب `data/enterprise/` جاهزة للنشر
(privacy-first لـ OEM + field-kiosk).

## English

**NexusLink v3.0.0** — the enterprise-weight release: a device that is
"manageable", "evidence-generating", and "born-private" — central policy
management, a tamper-evident audit trail, and OEM privacy-by-default, all
on-device with no cloud service and no byte leaving the local network.

### What's new

**Enterprise deployment (contract §38 — M4.1)** — a zero-schema central
policy schema v1: a `remoteAccess` field (`force-on`/`force-off`) and a
`blockedBridges` list; documented dual-path resolution
(`NEXUSLINK_POLICY_FILE`, then beside the pairing file, then
`.zstate/enterprise-policy.json`) with mtime caching and live enforcement in
the gateway (`force-off` applied before token decision + `policyBridgeGate`
on HTTP and WS + `policyManaged` in health) and in the routes
(`/api/remote-access` policy hints and conflict-action locks); a loopback
compliance report `/api/enterprise/compliance` with the policy file
fingerprint (sha256:16); an honest settings card that hides conflicting
buttons instead of silently disabling them; and the deployment guide
`docs/enterprise-deploy.md` with ready MDM templates (paths + silent
commands per platform + fingerprint verification) — the device is
"manageable" from a single MDM unit, zero manual touches.

**Trust-certificate evidence (contract §39 — M4.2)** — an on-device
enterprise audit trail: append-only JSONL with a hash chain
(`h = sha256:16` per line, `prev` the previous fingerprint — retroactive
tampering is detected, not prevented; the honest local-device model); a
single writer (the web server) with an internal queue, full chain
verification before every append, and `fsync` — evidence before speed; a
broken chain freezes the log (never append over broken evidence); a closed
event set: pairing actions with fingerprints (never tokens), admin denials
with full reasons (security evidence in itself), and policy transitions
`from→to` (change management); a loopback view `/api/enterprise/audit`
re-verifying the whole chain and reporting `brokenAt` and the head — a view,
never an action; plus an evidence-collection guide for the external auditor
with an independent Python verification script — the "evidence-generating"
device is auditor-ready (the certificate itself — SOC 2 Type I — remains an
external acceptance by the owner).

**OEM privacy-by-default (contract §40 — M4.3)** — a single environment
flag `NEXUSLINK_OEM_PRIVACY=1`, set by the system image
(systemd/launchd/Windows service), makes the device "born-private": with no
valid policy, all external access is rejected — even with a valid pairing
token (HTTP and WS) — and every bridge is blocked as a second defense;
fail-closed (a corrupt file never opens a born-private device — the inverse
of §38's deliberate user-mode fail-open toward the user); mitigation
exclusively via a valid §38 policy file (the MDM path — self-mitigation
locked by design); without the flag: the historical behavior, literally
unchanged; fully described in the compliance report and both settings cards,
with transitions recorded in the §39 log — built on the ready
`privacy-first.json` template with no new schema and no new file (the
§37/§38 pattern: one source of truth).

**Honest boundaries, as documented** — what remains external after this
release (enterprise acceptance, owner decision only): the actual silent
deployment on 50 devices (E1); the SOC 2 auditor and certificate (E2); the
first OEM contract and production lines (E3); and the tunnel/domain/TLS for
internet access, whose requirements are defined by a first enterprise
contract (E4 — the external side of §36.هـ.1). The local cores of all four
items are shipped and tested (§38 + §39 + §40 + WEB §36/PAIR §37).
