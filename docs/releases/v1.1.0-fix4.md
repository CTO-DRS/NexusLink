## العربية

**NexusLink v1.1.0** — التحديث الأكبر منذ الإصدار الأول: قناة إدخال حية فوق UDP، هاتفك شاشة ثانية حقيقية، لوحة رسم بقلم وضغط، ثلاثية تحكم متقدم بالحساسات، وكاميرا وميكروفون افتراضي بلا أي خطوة يدوية.

### جديد

**قناة NexusLive الحية (UDP)** — الإدخال الحي انتقل من socket.io (TCP) إلى قناة UDP مخصصة: بروتوكول ثنائي مضغوط (رأس 22 بايت، حزمة ≤34 بايت لكل حدث)، بوابة ثقة بمفتاح جلسة لكل تدفق، مزامنة إزاحة NTP-نمط عبر ping/pong، دمج حي (أحدث حالة تفوز)، وإحصاء فقد/ترتيب/RTT. القلم المفرد قِياسًا **P95 = 13ms** والبث المستمر 60Hz ‏**P50 = 8ms** — طرف-إلى-طرف حتى ما بعد الحقن.

**الهاتف شاشة ثانية فعلية** — على ويندوز: سائق شاشة افتراضية موقّع (VirtualDisplayDriver) يُثبَّت صامتًا مع المثبّت، بأوضاع 1080×2400 و2400×1080، ولمس فعلي على الشاشة الممتدة، وإطفاء ذكي عند انقطاع الهاتف. على لينكس (X11): بناء المخرج عبر xrandr. على ماك: القيد موثق بصدق مع بديل «بث نافذة محددة».

**لوحة الرسم الاحترافية** — التقاط خام 240Hz للقلم (ضغط/ميل/اتجاه كاملة)، محرك ضغط→فرشاة (مفاتيح [ و] أو Ctrl+عجلة، 2..64 مستوى، إيقاع ≤33/ث)، على لينكس لوحة افتراضية أصلية عبر uinput بضغط وميل وممحاة أصيلة، رفض راحة اليد، ومعاينة محلية فورية بسماكة الضغط. على ويندوز/ماك: تدهور رشيق للماوس المطلق (القيد موثق).

**ثلاثية التحكم المتقدم** — جيمباد الحساسات: بث 100Hz نشط حصرًا فوق القناة الحية، خرائط مفاتيح قابلة للتعيين بقوالب منصة/سباقات/قتال، عصا تقليب جاذبية بنافذة ميتة وهيستيريسيس. ماوس هوائي معاير: نقطة صفير 12 عينة، بوابة إمساك، حساسية 0.5..5×، فلتر EMA. عارض عروض: إيماءة معصم بتبريد، F5/PageUp/Down، ليزر Ctrl+L، ومؤقت يهتز على الهاتف. التفكيك حتمي في مسارين — لا مفتاح عالق أبدًا.

**الأجهزة الافتراضية + وسائط** — «NexusLink Camera» تظهر في Zoom/Meet **بلا أي خطوة يدوية** على ويندوز (مثبّت akvirtualcamera الرسمي 9.3.1 مرفق، تثبيت صامت، توفير idempotent بمعرف ثابت)، ميكروفون افتراضي بإعدادات في لوحة الأدوات، فيديو الهاتف يعمل في مشغل سطح المكتب عبر m3u مؤقت، سلسلة هاتف→TV عبر صفحة /tv لأي شاشة بمتصفح، وتبويب «الأجهزة الافتراضية» في الأدوات يعرض حالة كل جهاز (مثبت/نسخته/واجهته) مع فحصي تشخيص.

## English

**NexusLink v1.1.0** — the biggest update since the first release: a live UDP input channel, your phone as a real second display, a pressure-sensitive drawing tablet, an advanced sensor-based control trio, and zero-manual-step virtual camera & microphone.

### New

**NexusLive live channel (UDP)** — live input moved from socket.io (TCP) to a dedicated UDP channel: compact binary protocol (22-byte header, ≤34-byte datagram per event), per-stream trust gate with session key, NTP-style offset sync via ping/pong, live coalescing (latest state wins), and loss/order/RTT stats. Measured single pen event **P95 = 13ms**, continuous 60Hz stream **P50 = 8ms** — end-to-end, measured after injection.

**Phone as a real second display** — on Windows: a signed VirtualDisplayDriver installs silently with the app (1080×2400 and 2400×1080 modes), with real touch on the extended screen and smart power-off when the phone disconnects. On Linux (X11): the output is built via xrandr. On macOS: the limitation is honestly documented with a "cast a specific window" alternative.

**Professional drawing tablet** — raw 240Hz pen capture (full pressure/tilt/direction), pressure→brush engine ([ and ] keys or Ctrl+wheel, 2..64 levels, ≤33/s pacing), a native virtual tablet via uinput on Linux with genuine pressure/tilt/eraser, palm rejection, and instant local preview with pressure-width. On Windows/macOS: graceful fallback to absolute mouse (documented limitation).

**Advanced control trio** — sensor gamepad: 100Hz streaming active exclusively over the live channel, remappable keys with platformer/racing/fighting templates, gravity tilt-stick with deadzone and hysteresis. Calibrated airmouse: 12-sample zero point, grab gate, 0.5..5× sensitivity, EMA filter. Presentation remote: wrist gesture with cooldown, F5/PageUp/Down, Ctrl+L laser pointer, and a timer that vibrates on the phone. Deterministic teardown on both paths — no stuck keys, ever.

**Virtual devices + media** — "NexusLink Camera" appears in Zoom/Meet **with zero manual steps** on Windows (bundled official akvirtualcamera 9.3.1 installer, silent setup, idempotent provisioning with a fixed device ID), a virtual microphone with toolbox settings, phone video playing in the desktop system player via a temporary m3u, phone→TV via the /tv page on any browser screen, and a "Virtual devices" tools tab showing each device's status (installed/version/interface) with two diagnostics checks.

### What's new in fix4 (CI round fixes)

- Compilation fixes for the affected platform category from the first CI round (run 38818886866): Flutter mobile paths (controller_service/live_channel/gyro/tablet/controller_providers) and virtual-device plan hardening in media.rs — **no behavioral change** to any feature.
- Full validation round on the fix (run 38821566506): 3 test platforms + Android + iOS + 3 desktop platforms — all green.

### Release engineering

- Version **1.1.0** unified across all platforms (Windows/macOS/Linux/Android).
- Arabic/English release notes attached automatically to every release tag.
- Signed updater assets (latest.json + SHA256SUMS) are generated by the same green release pipeline.
- The **1.0.0 → 1.1.0** upgrade path is verified: update notification from Settings, signed install, and all settings & data preserved (the user's SQLite database is never touched; new tables are created additively only).

### Honest limitations

- macOS: the official camera pkg must be opened manually (CoreMediaIO signing constraints) — on Windows the install is fully silent.
- Native Chromecast (mDNS/cast protocol) is not supported — the /tv page is the supported path.
- Linux Wayland: no native input injection (X11/XWayland only).
- Windows SmartScreen: the binary is not Authenticode-signed — "More info → Run anyway" on first launch.
- iOS: no SMS/calls and some background services — Apple platform constraints.
